  \begin{block}{1. Introduction}

    Programs that ``look at'' a phone screen (screen readers, automated UI
    testers, software agents) need to know \emph{what} is on the screen and
    \emph{where} it is. Lightweight vision-language models (VLMs, $<$3B
    parameters) are fast enough for on-device use, but they make two kinds of
    systematic mistakes:

    \begin{itemize}
      \item \textbf{Element omission:} 10--30\% of visible elements are never
        reported (small icons, dividers, nested containers).
      \item \textbf{Misalignment:} bounding boxes deviate by tens of pixels
        from the true element positions.
    \end{itemize}

    These errors are consequences of compressing a large model into a small
    one. Training a bigger model is exactly what on-device constraints forbid.

  \end{block}

  \begin{block}{2. Existing Benchmarks}

    \begin{itemize}
      \item \textbf{RICO:} real Android screenshots with ground-truth
        interface elements, used for training and evaluation.
      \item \textbf{ScreenSpot:} GUI grounding benchmark spanning mobile,
        PC, and web layouts, used to test cross-domain transfer.
    \end{itemize}

  \begin{block}{3. Research Objectives}

    \begin{itemize}
      \item Correct the VLM's noisy element predictions \textbf{without
        retraining the VLM} or adding a second detector.
      \item Exploit the spatial structure that all well-designed interfaces
        share: alignment, containment, spacing, and grid membership.
      \item Fix both failure modes: \emph{repair} misplaced boxes and
        \emph{recover} entirely missed elements.
      \item Keep the correction cheap enough for on-device use
        (a 57K-parameter graph network, $<$1~ms per screenshot).
    \end{itemize}

  \end{block}

  \begin{block}{4. Proposed Methodologies}

    A screenshot is parsed by a lightweight VLM into a noisy element list,
    which is converted into a heterogeneous bipartite graph. GraphSAGE
    message passing then refines the elements, and the output is a corrected
    JSON with refined boxes, new proposals for missed elements, and
    per-element reliability scores.

\begin{column}{\colwidth}

    Two alternating hops of \textbf{GraphSAGE message passing} (mean
    aggregation):

    \begin{itemize}
      \item \emph{Hop 1:} element $\rightarrow$ constraint --- each constraint
        node aggregates its participating elements.
      \item \emph{Hop 2:} constraint $\rightarrow$ element --- each element
        aggregates the constraints it shares, forming its ``spatial
        neighbourhood.''
    \end{itemize}

    Element features: 4 normalized box coordinates + normalized area
    (5-d), optionally concatenated with frozen visual features (DINOv2).

  \begin{block}{5. Models}



    A two-layer bipartite GraphSAGE encoder (hidden dim 128, AdamW + cosine
    annealing) reads out four prediction heads, trained jointly on a
    weighted sum of losses:

    \begin{itemize}
      \item \textbf{Coordinate correction:} predicts per-element delta
        $\Delta\mathbf{x}_i$ (smooth L1) to repair misaligned boxes.
      \item \textbf{Violation detection:} classifies whether each constraint
        is broken --- makes the model ``understand'' layout rules.
      \item \textbf{Existence scoring:} scores whether each detection is real
        or hallucinated (binary cross-entropy).
      \item \textbf{Element completion:} randomly masks 20--80\% of
        ground-truth elements during training; dangling edges are the
        signature of missing elements, and the head proposes their boxes
        (IoU loss) and types. \emph{Self-supervised} --- no extra annotation.
    \end{itemize}

    Formally, the two hops are:

    \begin{equation*}
      \mathbf{h}_{c_j}^{(1)} = \sigma\!\Bigl(\mathbf{W}_1 \cdot
      \operatorname{MEAN}\!\bigl(\{\mathbf{h}_{e_i}^{(0)}: (e_i,c_j)\in
      \mathcal{E}_{\text{edge}}\}\bigr) + \mathbf{b}_1\Bigr),
    \end{equation*}

    \begin{equation*}
      \mathbf{h}_{e_i}^{(2)} = \sigma\!\Bigl(\mathbf{W}_2 \cdot
      \operatorname{MEAN}\!\bigl(\{\mathbf{h}_{c_j}^{(1)}: (e_i,c_j)\in
      \mathcal{E}_{\text{edge}}\}\bigr) + \mathbf{b}_2\Bigr),
    \end{equation*}

    All heads are trained jointly on the weighted sum

    \begin{equation*}
      \mathcal{L} = w_c\,\mathcal{L}_{\text{coord}} + w_v\,\mathcal{L}_{\text{vio}}
      + w_e\,\mathcal{L}_{\text{exist}} + w_p\,\mathcal{L}_{\text{prop}},
    \end{equation*}

    with default weights $w_c{=}1.0$, $w_v{=}0.5$, $w_e{=}0.5$, $w_p{=}0.5$.
    The completion head is self-supervised: masking ground-truth layouts
    creates the dangling-edge signal, so no extra annotation is needed.

  \end{block}

  \begin{block}{7. Conclusion \& Future Work}

    A heterogeneous bipartite GraphSAGE framework corrects noisy GUI element
    predictions from lightweight VLMs by encoding ten spatial constraint
    types as a graph and coupling coordinate correction, violation
    detection, existence scoring, and self-supervised element completion.

    \begin{itemize}
      \item 90--94\% violation accuracy on RICO.
      \item $+56\%$ IoU over nearest-neighbor completion at high drop
        ratios.
      \item $+2.0$pp F1 on 200 real Qwen3-VL Flash screenshots.
    \end{itemize}

    The gains appear when the VLM output is sparse; the framework inherits
    the VLM's initial detections and does not fix purely semantic errors.
    Generalization to desktop and web interfaces remains to be tested.

    \textbf{Future work} includes visual feature fusion with cross-attention,
    which early experiments show improves proposal MSE by 18--22\%, domain
    adaptation to ScreenSpot, and temporal context to distinguish missing
    elements from elements hidden by UI state.

  \end{block}
